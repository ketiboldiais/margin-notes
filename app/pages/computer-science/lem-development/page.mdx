## Lexical Analysis
Lexical analysis is the process of taking a sequence of source-code characters and grouping those characters into meanintful units called __tokens__. Lexical analysis involves three distinct concepts:

1. __Tokens__. A _token_ is a pair ${\lpar t, x \rpar,}$ where ${t}$ is a _token name_ and ${x}$ is some value. The token name is an abstract symbol representing a kind of lexical unit (e.g., a keyword, an identifier, a Boolean value like true or false, etc.) Token names are what the parser processes. The ${x}$ value could be whatever value we deem fit for the token name. For example, the sequence of characters ${25}$ could be lexically analyzed as ${\lpar \texttt{integer}, 25 \rpar.}$ Here, the token name is ${\texttt{integer}}$ and the value is the literal integer ${25.}$ 
2. __Patterns__. A _pattern_ is a description of the form that the lexemes of a token can take. For example, in LEM, a token named `Bool` encompasses all lexemes with the following patterns: `true` or `false`. The patterns, of course, can be more complicated: A `float`, for example, is either (1) an `integer`, followed by dot ("`.`") followed by an integer, or (2) a dot followed by an integer.  
3. __Lexemes__. A _lexeme_ is the actual sequence of characters in the source program that matches the pattern for a token. When a sequence matches a pattern, the lexical analyzer identifies that sequence and yields an instance of the corresponding token.

### `Token` Objects
LEM tokens are represented by `Token` objects. Below are its properties and methods.

#### _`Token`_`._name`
The LEM token's name. The value of this property is one of [`TokenName`](#tokenname).

#### _`Token`_`._lexeme`
The LEM token's lexeme. The value of this property is a string, corresponding to the lexeme scanned.

#### _`Token`_`._literal`
The LEM token's corresponding JavaScript value, if any. The value of this property is a [Primitive](#primitives). 

#### _`Token`_`._line`
A JavaScript _number_ corresponding to the line within the source code where the token was scanned.

#### _`Token`_`.clone()`
Returns a new instance of the token, with all the same properties. 

#### _`Token`_`.name(𝑛)`
Given a [`TokenName`](#tokenname) 𝑛, returns a new instance of the token with all the same properties, except the new instance's property [`_name`](#token_name) is now 𝑡.

#### _`Token`_`.line(ℓ)`
Given a JavaScript _number_ ℓ, returns a new instance of the token with all the same properties, except the new instance's [`_line`](#token_line) is now ℓ.

#### _`Token`_`.lit(𝑝)`
Given a [Primitive](#primitives) 𝑝, returns a new instance of the token with all the same properties, except the new instance's [`_literal`](#token_literal) property is now 𝑝.

#### _`Token`_`.isNamed(𝑛)`
Given a [TokenName](#tokenname) 𝑛, returns true if the given `Token`'s name matches 𝑛 and false otherwise.

#### Primitives
Within LEM's source code, the type `Primitive` is used to refer to the following JavaScript types:

1. `string`
2. `number`
3. `null`
4. `boolean`.

## Error Handling
LEM represents errors with `Glitch` objects. The following sections outline a `Glitch` object's properties and methods. 

### `Glitch` Objects
#### _`Glitch`_`._message`
A JavaScript string corresponding to the `Glitch` object's message.

#### _`Glitch`_`._type`
The `Glitch` object's [type](#glitchtype).

#### _`Glitch`_`._line`
The line where the `Glitch` object was scanned on. The value of this property is a JavaScript _number_. 

#### _`Glitch`_`.report()`
Returns a JavaScript _string_ explaining the _Glitch_. In short, the `Glitch`'s error message with additional information in a pretty-print format.

#### _`Glitch`_`.clone()`
Returns a copy of the `Glitch` object.

#### _`Glitch`_`.line(ℓ)`
Given an argument ℓ (a JavaScript _number_), returns a copy of the `Glitch` with its [`_line` property](#glitch_line) set to ℓ. 

#### _`Glitch`_`.type(𝑡)`
Given an argument 𝑡 (a [`GlitchType`](#glitchtype)), returns a copy of the `Glitch` with its [`_type` property](#glitch_type) set to 𝑡.

### `GlitchType`
In LEM, `Glitch` objects can be one of five types: 

1. `lexical-error`: A `Glitch` that occurred during the scanning or tokenization process.
2. `syntax-error`: A `Glitch` that occurred during the parsing process.
3. `type-error`: A `Glitch` that occurred during the type-checking process.
4. `environment-error`: A `Glitch` that occurred during an environment lookup.
5. `runtime-error`: A `Glitch` that occurred during the interpretation/execution process.

### `glitch(𝑚,𝑡,ℓ,𝑐)`
This function creates and returns a new [`Glitch`](#glitch-objects). The function takes three arguments:

1. `𝑚`: The Glitch's message (i.e., error message).
2. `𝑡`: The Glitch's [type](#glitchtype).
3. `ℓ`: The line where the `Glitch` occurred.
4. `𝑐`: The column where the `Glitch` occurred.

## Parsing
Once Weaver has scanned the LEM source code, the generated tokens are sent to the parser. The parser takes these tokens and constructs an _abstract syntax tree_ (_AST_). The AST, at the highest level, is a sequence of statements.

### Utility Type: Option
Within LEM's source code, you'll find that some functions return the type `Some<T>` or `None`, where `T` is some arbitrary type. LEM takes a functional approach to dealing with potential absences of values. In general: 

$$
  \texttt{Option<𝑥>} = \texttt{Some<𝑥>} ~|~ \texttt{None} 
$$

### Addition
The `+` operator performs basic algebraic addition. The following type rules apply.

| `+`         | `int`     | `float`   | `frac`    | `imaginary` | `complex` |
| ----------- | --------- | --------- | --------- | ----------- | --------- |
| `int`       | `int`     | `float`   | `frac`    | `complex`   | `complex` |
| `float`     | `float`   | `float`   | `float`   | `complex`   | `complex` |
| `frac`      | `frac`    | `float`   | `frac`    | `complex`   | `complex` |

| `complex`   | `complex` | `complex` | `complex` | `complex`   | `complex` |

If either the left or right operands are unresolved symbols, the result is a sum.

## Num
### `gcd(𝑎,𝑏)`
Given two numbers ${a}$ and ${b,}$ returns the greatest common divisor of ${a}$ and ${b.}$

### `simplestFraction(𝑎,𝑏)`
Given the fraction ${a/b,}$ returns ${n/m,}$ where ${n/m}$ is the simplest form of ${a/b.}$ The returned value is a pair ${\lbracket n, m \rbracket.}$

### `bigSign(𝑥)`
Returns the sign of the given `bigint` ${x}$ as one of the `bigint`s ${1,}$ ${-1,}$ or ${0.}$

$$
\texttt{bigSign}(x) = 
  \begin{cases}
    -1 & \text{if} ~~ x ~\lt~ 0 \\
    1 & \text{if} ~~ x ~\gt~ 0 \\
    0 & \text{else}
  \end{cases}
$$

### `bigAbs(𝑥)`
