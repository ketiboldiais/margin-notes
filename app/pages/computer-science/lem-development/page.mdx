### `Token` Objects
LEM tokens are represented by `Token` objects. Below are its properties and methods.

#### _`Token`_`._type`
The LEM token's specific type. The value of this property is one of [TokenType](#tokentype).

#### _`Token`_`._lexeme`
The LEM token's lexeme. The value of this property is a string, corresponding to the lexeme scanned.

#### _`Token`_`._literal`
The LEM token's corresponding JavaScript value, if any. The value of this property is a [Primitive](#primitives). 

#### _`Token`_`._line`
A JavaScript _number_ corresponding to the line within the source code where the token was scanned.

#### _`Token`_`.clone()`
Returns a new instance of the token, with all the same properties. 

#### _`Token`_`.type(𝑡)`
Given a [TokenType](#tokentype) 𝑡, returns a new instance of the token with all the same properties, except the new instance's property [`_type`](#token_type) is now 𝑡.

#### _`Token`_`.line(ℓ)`
Given a JavaScript _number_ ℓ, returns a new instance of the token with all the same properties, except the new instance's [`_line`](#token_line) is now ℓ.

#### _`Token`_`.lit(𝑝)`
Given a [Primitive](#primitives) 𝑝, returns a new instance of the token with all the same properties, except the new instance's [`_literal`](#token_literal) property is now 𝑝.

#### Primitives
Within LEM's source code, the type `Primitive` is used to refer to the following JavaScript types:

1. `string`
2. `number`
3. `null`
4. `boolean`.

## Error Handling
LEM represents errors with `Glitch` objects. The following sections outline a `Glitch` object's properties and methods. 

### `Glitch` Objects
#### _`Glitch`_`._message`
A JavaScript string corresponding to the `Glitch` object's message.

#### _`Glitch`_`._type`
The `Glitch` object's [type](#glitchtype).

#### _`Glitch`_`._line`
The line where the `Glitch` object was scanned on. The value of this property is a JavaScript _number_. 

#### _`Glitch`_`.report()`
Returns a JavaScript _string_ explaining the _Glitch_. In short, the `Glitch`'s error message with additional information in a pretty-print format.

#### _`Glitch`_`.clone()`
Returns a copy of the `Glitch` object.

#### _`Glitch`_`.line(ℓ)`
Given an argument ℓ (a JavaScript _number_), returns a copy of the `Glitch` with its [`_line` property](#glitch_line) set to ℓ. 

#### _`Glitch`_`.type(𝑡)`
Given an argument 𝑡 (a [`GlitchType`](#glitchtype)), returns a copy of the `Glitch` with its [`_type` property](#glitch_type) set to 𝑡.

### `GlitchType`
In LEM, `Glitch` objects can be one of five types: 

1. `lexical-error`: A `Glitch` that occurred during the scanning or tokenization process.
2. `syntax-error`: A `Glitch` that occurred during the parsing process.
3. `type-error`: A `Glitch` that occurred during the type-checking process.
4. `environment-error`: A `Glitch` that occurred during an environment lookup.
5. `runtime-error`: A `Glitch` that occurred during the interpretation/execution process.

### `glitch(𝑚,𝑡,ℓ,𝑐)`
This function creates and returns a new [`Glitch`](#glitch-objects). The function takes three arguments:

1. `𝑚`: The Glitch's message (i.e., error message).
2. `𝑡`: The Glitch's [type](#glitchtype).
3. `ℓ`: The line where the `Glitch` occurred.
4. `𝑐`: The column where the `Glitch` occurred.
